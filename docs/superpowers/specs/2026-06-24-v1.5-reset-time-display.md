# V1.5 Reset Time Display — Design Spec

## Goal

Add Codex/Kimi reset-time display to the CLI, UI expanded cards, and collapsed summary, without changing existing percentage behavior or breaking any existing commands, tests, or EXE packaging.

## In Scope

1. Parse and preserve `resetAt` for Codex and Kimi windows.
2. Add `core/time_display.py` formatting helpers.
3. Update CLI `refresh` / `status` output to include reset times.
4. Update UI ProviderCard to show three columns: `5H / WEEK`, percent, reset time.
5. Update UI collapsed summary with optional reset-summary line.
6. Add `ui.show_reset_times`, `ui.reset_display_mode`, `ui.compact_summary_show_reset` config keys.
7. Add tests for reset parsing, formatting, and summary formatting.
8. Update README and docs; create `docs/ui_notes.md`.

## Out of Scope

- Tauri / hardware / architecture changes.
- Countdown display mode (config key accepted, but only `time` mode is implemented).
- Large UI redesign.

## Data Schema

Codex/Kimi provider result already contains:

```json
{
  "fiveHour": {"remainingPercent": 99, "usedPercent": 1, "resetAt": "..."},
  "weekly": {"remainingPercent": 75, "usedPercent": 25, "resetAt": "..."}
}
```

`resetAt` may be `null`, missing, or any parseable/unknown string. Percent fields remain authoritative.

## Reset Parsing Rules

### Kimi

Source: `kimi-usage --json` list items with labels `5h Limit` and `Weekly Usage`.

- `label == "5h Limit"` → `fiveHour.resetAt`
- `label == "Weekly Usage"` → `weekly.resetAt`
- Missing `reset_at` is allowed; do not mark provider invalid.
- Preserve raw string value; reformat for display via `format_reset_time()`.

### Codex

Try field aliases in each window context:

```text
resetAt
reset_at
resetsAt
resets_at
primary.resetAt
primary.resetsAt
secondary.resetAt
secondary.resetsAt
fiveHour.resetAt
weekly.resetAt
rate_limit.primary_window.reset_at
rate_limit.secondary_window.reset_at
```

Mapping:

- 5H / primary window → `fiveHour.resetAt`
- weekly / secondary window → `weekly.resetAt`
- Missing reset time leaves `resetAt` as `null`.
- Stale fallback preserves the old window object, including old `resetAt`.

## Display Format

`core/time_display.py`:

```python
format_reset_time(reset_at: str | None, now: datetime | None = None) -> str
format_reset_countdown(reset_at: str | None, now: datetime | None = None) -> str
```

Supported input formats:

- ISO: `2026-06-18T18:44:00+08:00`
- Short: `06-18 18:44`
- Time only: `18:44`

Behavior:

- `None`/empty → `"--"`
- Unparseable raw string → return raw string (or `"--"` if caller prefers)
- Expired → `"soon"` or raw time
- Windows CLI uses ASCII

### CLI Output

```text
CODEX
  5H     99%   reset 18:44
  Week   75%   reset Wed 10:00
  Status ok

KIMI
  5H     70%   reset 18:44
  Week   52%   reset 06-25 13:44
  Status ok
```

If reset unavailable:

```text
5H     99%   reset --
```

### UI Expanded Card

```text
CODEX                         ok
5H      99%        18:44
WEEK    75%        06-25
```

or, if space allows:

```text
5H      99%        reset 18:44
WEEK    75%        reset 06-25
```

Reset missing shows `--`. Stale fallback shows old value; status label shows `offline`.

### UI Collapsed Summary

Default single line:

```text
C 99/75  K 70/52  DS 58.23
```

Optional second line when `compact_summary_show_reset: true`:

```text
R C18:44 K18:44    Fresh
```

If reset unavailable, shows `--` for that provider.

## Config Keys

Merge into existing `ui` section:

```yaml
ui:
  show_reset_times: true
  reset_display_mode: "time"
  compact_summary_show_reset: true
```

Default values are shown above. Existing `ui` keys must be preserved.

## Error Handling

- Provider cards show only short status words: `ok`, `offline`, `error`, `unsupported`, `key not configured`.
- Full provider message remains in `message` field but is hidden in the small card.
- Tooltip may show details later; not required for V1.5.

## Security

- Never print real API keys, Bearer tokens, Codex auth.json content, or cookies.
- Do not ship `.env` in release.
- Existing `sanitize_data`/`sanitize_message` continue to apply.
