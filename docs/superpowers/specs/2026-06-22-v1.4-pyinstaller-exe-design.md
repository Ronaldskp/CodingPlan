# V1.4 PyInstaller EXE Packaging Design

## Goal
Deliver a Windows desktop EXE (`CodingPlanWidget.exe`) that launches the existing PySide6 widget without a console window, while preserving the existing Python source workflow and keeping all secrets/config/data outside the binary.

## Context
- Project: `E:\Ronald\CodingPlanWidget`
- Stack: Python 3.10+, PySide6, PyYAML, python-dotenv, pytest
- V1.3 already supports Codex, Kimi, DeepSeek providers; system tray; desktop shortcut; VBS silent launcher; CLI commands.
- Virtual environment: `E:\Ronald\CodingPlanWidget\codingplan`

## Constraints
1. Do not modify files outside the project directory.
2. Do not delete `CodingPlanWidget_start_plan.md`, existing `.bat`, `.vbs`, or shortcut scripts.
3. Never embed real API keys, tokens, cookies, or Codex `auth.json` into the EXE or release folder.
4. `.env` must remain an external file read at runtime.
5. `config.yaml`, `data/`, `assets/` must remain external.
6. Preserve existing CLI behavior:
   - `python main.py doctor`
   - `python main.py refresh`
   - `python main.py status`
   - `python main.py widget`
7. Do not restructure into Tauri or hardware firmware.
8. Keep provider/core/ui layering intact.

## Design Decisions

### 1. Path Handling: `core/paths.py`
Introduce a single source of truth for runtime paths so the same code works from source and from the EXE.

- `project_root()`: returns the directory that should contain `.env`, `config.yaml`, `data/`, `assets/`.
  - Source run: `Path(__file__).resolve().parent.parent` (i.e. `E:\Ronald\CodingPlanWidget`).
  - PyInstaller run: `Path(sys.executable).parent` (the folder containing `CodingPlanWidget.exe`).
  - `sys._MEIPASS` is **only** used for bundled internal resources, never for writable data.
- `data_path(relative="")`, `config_path()`, `dotenv_path()`, `assets_path(relative="")`: helpers built on `project_root()`.
- `ensure_data_dir()`: creates `data/` under the runtime root if missing.

Rationale: centralizing paths avoids the common PyInstaller mistake of treating `sys._MEIPASS` as the project root and trying to write there.

### 2. GUI Entry Point: `app_launcher.py`
A tiny, dedicated module for the EXE:

```python
from main import main

if __name__ == "__main__":
    main(["widget"])
```

`main.py` will be updated to accept an optional `argv` argument:

```python
def main(argv=None) -> int:
    args = build_parser().parse_args(argv)
    ...
```

When called without arguments (`python main.py ...`) the default `argparse` behavior is unchanged. When called from `app_launcher.py` it always runs `widget`.

Rationale: keeps CLI entry point and GUI entry point separate; PyInstaller `--noconsole` build does not need argument parsing logic in the EXE.

### 3. PyInstaller Configuration: `CodingPlanWidget.spec`
- Mode: **onedir** (recommended by the user; faster PySide6 startup, easier debugging).
- Name: `CodingPlanWidget`
- Console: `None` (`--noconsole`)
- Icon: `assets/coding_plan.ico`
- Output: `dist/CodingPlanWidget/`
- Hidden imports: none expected beyond what PyInstaller auto-detects for PySide6; add `PySide6` hook if needed.
- Datas: include `assets/coding_plan.ico` so the icon resource is available inside the bundle (the running app still resolves the external icon first).
- Do **not** bundle `.env`, `data/usage.json`, `data/deepseek_daily.json`, Codex `auth.json`, or any provider credentials.

### 4. Build Script: `build_exe.bat`
Automates the full packaging workflow:
1. Verify `codingplan\Scripts\python.exe` exists.
2. Install PyInstaller if missing (or verify it is installed).
3. Clean `build/`, `dist/`, `release/CodingPlanWidget/`.
4. Run PyInstaller using `CodingPlanWidget.spec`.
5. Assemble release package:
   - Copy `dist/CodingPlanWidget/` -> `release/CodingPlanWidget/`
   - Copy `config.yaml`
   - Copy `.env.example`
   - Copy `assets/coding_plan.ico`
   - Create empty `data/` with `.gitkeep` and a short `README.md`
   - Generate `README_RELEASE.md`
6. Refuse to copy real `.env`, `usage.json`, `deepseek_daily.json`, or `auth.json`.
7. Pause on error so the build log remains visible.

### 5. Runtime Behavior
When `release/CodingPlanWidget/CodingPlanWidget.exe` starts:
1. `project_root()` resolves to `release/CodingPlanWidget/`.
2. `.env` is loaded from that directory.
3. `config.yaml` is loaded from that directory; if missing, falls back to built-in defaults.
4. `data/` is created if absent.
5. `data/usage.json`, `data/ui_state.json`, `data/deepseek_daily.json` are written there.
6. Provider collection uses the external environment and config; Codex reads `~/.codex/auth.json` from the user profile as before.

### 6. Tests
- `tests/test_paths.py`
  - Source mode root resolution.
  - Simulated EXE mode root resolution (monkeypatch `sys.frozen`, `sys.executable`, `sys._MEIPASS`).
  - `ensure_data_dir()` creates missing directory.
  - Asset path fallback does not crash when icon is missing.
- `tests/test_release_safety.py`
  - After `build_exe.bat` runs, assert `release/CodingPlanWidget/.env` does not exist.
  - Assert no JSON/text file under `release/CodingPlanWidget/` contains `KIMI_API_KEY`, `DEEPSEEK_API_KEY`, bearer tokens, or JWT-like strings.
  - Assert `data/` does not contain `usage.json` or `deepseek_daily.json` in the release template.

### 7. Documentation
- Update `README.md` with EXE launch instructions and build command.
- Update `docs/development_log.md` with V1.4 notes.
- Create `docs/packaging_notes.md` covering:
  - Why PyInstaller.
  - Why onedir over onefile.
  - Entry point (`app_launcher.py`).
  - External config/data behavior.
  - Why `.env` is not embedded.
  - Release layout.
  - Troubleshooting (PySide6 plugin missing, icon missing, .env not read, data not writable, antivirus false positives).
  - Future options (onefile, installer, autostart).
- Generate `release/CodingPlanWidget/README_RELEASE.md` for end users.

## Security Properties
- No real secrets are written into `CodingPlanWidget.spec`, the EXE, or any release file.
- The build script copies only `.env.example`, not `.env`.
- `sanitize_data` remains in effect for all JSON caches.
- Doctor/status/refresh never print real credentials.

## Acceptance Criteria
1. `python main.py doctor/refresh/status/widget` still work from source.
2. `python -m pytest -q` passes.
3. `build_exe.bat` completes without errors.
4. `release/CodingPlanWidget/CodingPlanWidget.exe` launches the widget with no console window.
5. Tray icon, window hide/show, tray Exit all work.
6. External `.env`, `config.yaml`, and `data/` are read/written in the release directory.
7. Kimi/DeepSeek display `unsupported` when keys are absent; Codex fails gracefully.
8. Release folder contains no real `.env`, no `auth.json`, no cached usage data, and no embedded keys.

## Out of Scope
- OneFile EXE (can be evaluated later).
- Windows installer/MSI.
- Code signing.
- Autostart service.
- EXE CLI surface (`--doctor`, etc.). The EXE is widget-only for V1.4.
